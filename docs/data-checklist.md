# 待校订数据清单

前端已跑通，但**所有业务数据都是占位**。这份清单按模块列出需要人工核对/替换的字段，
以及核对完之后的验收动作。建议顺序：P0（用户一眼就能看出真假）→ P1（细节）→ P2（可后置）。

图例：`[ ]` 未处理 · `[x]` 已校订 · **P0/P1/P2** 优先级

---

## 1. `src/data/types.ts` —— 数据契约（P0）

- [ ] 字段与未来后端接口对齐后再冻结；改动只允许「新增可选字段」，不要改名。
- [ ] `Song.audioUrl` / `Song.lyrics` 留空即走模拟播放与占位歌词，接后端前不要填来源不明的链接。
- [ ] `Video.videoUrl` / `poster` 同上。

## 2. `src/data/albums.ts` —— 专辑（P0）

需核对：`name`、`year`、`date`、`type`（studio / live / ep / single / compilation）、`description`、`songIds` 收录顺序。

- [ ] 逐张对照官方唱片目录：发行日期精确到日，类型不要混用 EP 与录音室专辑。
- [ ] `description` 现在是人写的介绍句，正式版改为乐评/内页文案或留空（**不要照抄他人文字**）。
- [ ] `songIds` 与 `songs.ts` 里 `albumId` 必须双向一致（当前由 id 前缀对齐，需再核一遍漏项）。

## 3. `src/data/songs.ts` —— 曲目（P0/P1）

行格式：`[标题, 专辑 id, 时长秒, BPM, 原调, Capo, 难度, 标签, 演示播放量, 城市?]`

- [ ] **P0** 曲名与所属专辑、发行年份。
- [ ] **P0** `lyrics` 字段目前全部为空 → 前端生成结构占位歌词。填入真实歌词前必须拿到授权。
- [ ] **P1** `duration`：以官方音源时长为准（现在按 4:30 上下估写）。
- [ ] **P1** `bpm` / `key` / `capo` / `difficulty`：这三项是「工具」模块的核心，需以实际演奏版本核对；
      现场版与录音室版不同，考虑后续拆 `version` 字段。
- [ ] **P2** `playCount`：现在是编的数，接后端后由统计接口覆盖，前端只读。
- [ ] **P2** `tags` / `city`：影响搜索、分类、按城市听歌、彩蛋判定（`easterEggs.rainSongIds` 依赖城市），
      标签词表建议收敛为固定枚举。

## 4. `src/data/videos.ts` —— 影像（P1）

- [ ] 标题、年份、城市、时长、关联曲目。
- [ ] `description` 现为占位说明，不要照搬节目文案。
- [ ] 分类枚举 `live / mv / documentary / behind` 是否与运营口径一致。
- [ ] `videoUrl`：确认授权范围（站内嵌 / 外链跳转 / 不公开）；无授权时保持留空 → 用 Canvas 放映机演示。

## 5. `src/data/chords.ts` —— 和弦库与谱表（P0）

- [ ] `chordLibrary` 指型（frets / fingers / barre）需吉他手弹一遍验证，特别是 `B♭`、`F♯m`、`Cadd9`、`Dsus2`。
- [ ] `sheets[*]`：`tuning`（是否变调夹与特殊定弦）、`tempoMark`、`sections[*].chords` 走向、`lines` 段落行数。
- [ ] **不做**任何歌词转录：`sections.lines` 只是数字，页面显示为段落占位。
- [ ] `usedChords` 与各段落和弦保持一致（当前由人工填写，考虑改为构建时派生）。
- [ ] 谱的覆盖度：现在只录入曲库的一部分，需补齐常用曲目或明确「未录入」策略。

## 6. `src/data/bio.ts` —— 人物资料（P0）

- [ ] `profile`：生日（`birthday` 用于生日彩蛋判定）、出身地、活跃年份、代表作、`roles`、`genres`。
- [ ] `chapters` 分章简介：**全部为占位叙事**，正式版需替换为已核实资料，且避免抄写他人文章。
- [ ] `facts`、`bandMembers`（乐队成员现在只有占位名目）、`faqs`、`awards`。
- [ ] `data/tour.ts` 的 `timeline`： album / tour / life / other 四类事件日期与描述。

## 7. `src/data/tour.ts` —— 叁叁肆巡演（P0）

- [ ] `RAW` 城市表：省份归属、城市名、已完成年份（`城市@2018`）。现在约 300 余个条目里只标了几十个已完成。
- [ ] `TOUR_TARGET = 334`、`TOUR_NAME`、`TOUR_SLOGAN` 与官方口径核对。
- [ ] `VENUES` 场地名是按省+序号轮询生成的**假数据**，不能当作真实场地；需逐场对应。
- [ ] 每年实际场数（页面「按年」视图与统计条）需与官方记录一致。
- [ ] 计划中城市 `year: 0` 的展示策略（现在显示为「计划中」）。

## 8. `src/data/sponsors.ts` —— 赞助（P0）

- [ ] 档位名称、`monthly` / `yearly` 金额、`benefits` 权益清单、`featured` 推荐档。
- [ ] `payChannels` 二维码与收款主体：**上线前必须换成真实收款渠道**，当前渲染的是算法生成的伪二维码占位。
- [ ] `useCases`（钱花在哪）、`sponsorStats`、`sponsorWall`（留言墙现在是示例昵称）。
- [ ] 法务口径：赞助 ≠ 会员权益兑换，页面文案与真实规则核对。

## 9. `src/data/quotes.ts` —— 语录与首页横幅（P0）

- [ ] `quotes` 文案：现在全部是自己写的句子，**若替换为真实歌词/发言需授权**。
- [ ] `banners` 的标题、副标题、跳转路径。

## 10. `src/data/achievements.ts` —— 成就与彩蛋（P2）

- [ ] 12 个成就的阈值（播放次数、完整听完、连续天数、收藏数、专辑覆盖、变调夹换算、深夜收听）。
- [ ] `easterEggs.rainSongIds`：与 `songs.ts` 的 `city`/`tags` 判定耦合，改数据时同步。

## 11. 页面级验收（每校订完一个模块就跑一遍）

- [ ] `npm run typecheck` 无报错。
- [ ] 主页：每日推荐换天变化、续播提示、巡演进度环比例正确。
- [ ] 歌曲页：分类 / 标签 / 城市筛选结果数与预期一致；列表双击可播。
- [ ] 专辑页：曲目数、总时长、上下张跳转不越界。
- [ ] 播放台 / 全屏 / 播放条：进度、歌词高亮、队列操作（上移/下移/移除）互不冲突。
- [ ] 搜索：`?q=` 复现、5 个 tab 计数与结果条数一致。
- [ ] 工具：节拍器 4/4、3/4、6/8 重音正确；调音器静音时不闪值；变调夹换算与原调/目标调组合全覆盖。
- [ ] 更多：年表分节、城市对应曲目、报告空态与有数据态都好看。
- [ ] 赞助：档位月/年切换、支持记录增删、导出备份含 `sponsor.*`。
- [ ] 设置：所有开关刷新后仍在；导出 → 清空 → 导入 能完整还原。

## 12. 替换成后端时要一起补的东西

- [ ] 分页 / 游标（历史、巡演清单、搜索结果）。
- [ ] 用户身份与云同步（现在一切本机）。
- [ ] 真实播放上报（现在由 `recordPlay` / `recordFinish` 本地模拟）。
- [ ] 授权内容校验（歌词、音频、影像的来源标记字段，例如 `licensed: boolean` + `source`）。
